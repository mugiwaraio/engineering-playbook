# Codex 代码开发规则

## 上下文范围

进行代码分析、功能开发、代码修改和问题排查时，只读取与当前任务直接相关的源代码和配置文件。

优先读取：

- `package.json`
- `src/`
- `app/`
- `server/`
- `test/`
- `tests/`
- `config/`
- 与当前任务直接相关的文档

除非用户明确要求，否则不要读取、搜索、列出或分析：

- `node_modules/`
- `dist/`
- `build/`
- `out/`
- `.next/`
- `.nuxt/`
- `.output/`
- `coverage/`
- `.cache/`
- `.turbo/`
- `.npm/`
- `.pnpm-store/`
- `logs/`
- `tmp/`
- `temp/`
- Source map 文件
- 压缩后的 JS 或 CSS 文件
- 日志文件
- 自动生成文件

## 搜索规则

- 优先使用 `git ls-files`、`rg --files` 或默认的 `rg` 搜索项目文件（后两者默认遵循 `.gitignore`，且能覆盖未提交的新文件）。
- 搜索时遵循 `.gitignore`。
- 不要使用 `rg --no-ignore`、`rg -uuu` 或其他绕过忽略规则的参数。
- 不要直接执行 `find .`、`grep -R .` 或递归列出整个项目。
- 搜索前先限定到相关源代码目录。
- 不要为了了解项目结构而递归列出 `node_modules`。

## 依赖目录

普通业务开发不得读取或修改 `node_modules/`。

仅在以下情况允许读取指定依赖包：

- 排查第三方依赖自身的问题
- 确认依赖的类型声明或实际导出
- 用户明确要求检查依赖源码

需要检查依赖时，只读取具体包目录，不要扫描整个 `node_modules/`。

## 上下文控制

- 不要一次性读取大量无关文件。
- 先定位入口文件和调用链，再按需读取文件。
- 已经获得足够信息后，停止继续扩大搜索范围。
- 不要将构建产物、依赖源码、日志或缓存文件加载到上下文中。
